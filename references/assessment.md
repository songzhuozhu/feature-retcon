# 只读评估与执行确认

本文件是评估分支的单一事实来源。

## 权威解析

按以下优先级确定权威根：

1. 用户明确指定的路径。
2. 仓库声明的入口、索引或配置。
3. 产物内部的状态、替代关系和引用闭包。
4. Git 历史仅作支持证据。

编号更大、日期更新或提交更晚都不能单独证明权威性。候选无法排除时，列出证据并让用户裁决。

## 评估边界

评估只允许读取文件、目录、Git 状态和历史，以及运行不会改变文件、索引、远端或外部系统的命令。不得在评估期创建契约、修正文档、初始化 Git、安装依赖或执行生成器。

逐个工作根记录：

- 绝对路径和职责。
- 是否为当前权威根、开发根或验证根。
- Git 仓库边界、分支、基线引用和未提交状态。
- 本轮建议只读或可写。
- 原生验证命令及其副作用。

当前目录下未被用户确认的其他根保持只读。没有 Git 不阻塞评估；执行前必须提示缺少可恢复基线、建议纳入 Git，并取得风险确认。

## 工作树冲突

将未提交修改与影响闭包按路径和语义比较：

- 不重叠：记录并保持不变。
- 重叠：暂停执行，让用户选择它是当前权威基线的一部分、应纳入本轮，还是先由用户处理。
- 无法判断：按重叠处理。

不得自动暂存、stash、合并、覆盖或还原用户修改。

## 影响闭包

从变更断言出发，按派生、实现、验证和引用关系构建产物依赖图。把产物映射到需求、设计、任务、实现、验证五个语义阶段，而不是映射到固定文件名。

统计每个可选目标阶段至少涉及：

- 工作根和 Git 仓库数。
- 修改、创建、删除文件数。
- API、数据结构、状态或流程数。
- 保留、重置、删除、拆分、合并和新增任务数。
- 测试、构建、迁移和验证命令数。
- 外部副作用、敏感候选和当前不可验证项数。

使用数字描述影响，不使用“小、中、大”代替事实。

## 删除清单

单独列出预计删除的文件、章节、任务、测试、配置和代码路径，以及每项删除的理由、活跃引用和恢复方式。用户确认覆盖清单内删除；执行中发现新的重要删除属于实质范围扩张。

## Hook 与副作用

列出项目声明的 Hook、生成器、格式化器和检查器，并分为：

- 授权闭包内的本地写入：确认后可运行。
- Git、网络、外部系统或新增工作根写入：需要单独授权。
- 可选 Hook：默认不运行。
- 声明为 mandatory 但越过边界：保持阻塞。

## 固定评估报告

每次只读评估按以下顺序输出：

1. **变更断言草案**：被推翻行为、当前目标、保持不变、排除项、兼容与迁移影响。
2. **权威依据**：候选、判定证据和未知项。
3. **追平水位**：当前最深已同步阶段及更深的阶段陈旧状态。
4. **产物依赖图**：阶段、派生关系和引用闭包。
5. **工作根与权限**：路径、仓库、文件数量及建议读写边界。
6. **冲突与风险**：重叠修改、无 Git、敏感载荷、迁移和不可验证项。
7. **删除清单**：预计删除及恢复方式；没有时明确写零项。
8. **目标阶段选项**：逐项给出量化影响。
9. **推荐**：只给一个建议阶段及其理由，同时说明用户对改动大小负责。
10. **验证计划**：基线、原生检查、静态检查和无法证明的部分。
11. **确认请求**：要求用户确认断言、阶段、可写根、删除、冲突处置和特殊授权。

任何栏目没有结论时写明缺失证据和取得方式，不用推测填空。

## 执行确认

执行确认必须覆盖：

- 完整变更断言。
- 一个目标追平阶段。
- 每个可写工作根。
- 删除清单。
- 重叠工作树修改的处置。
- 无 Git 风险确认。
- Hook 和外部副作用授权。
- 敏感文件与大恢复载荷的逐项选择。

用户只回复“接受”时，仅继承紧邻上一份评估中明确列出的内容；评估之后出现的新范围不能被该回复隐式授权。
