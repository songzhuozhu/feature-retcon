# 合成案例目录

以下案例全部为虚构内容，用于校准 Skill 行为。

## 只追平需求

某导出功能已经完成任务拆解，用户把“默认生成 PDF”改为“由用户选择 PDF 或 CSV”，并决定本轮只重写规格和直接契约。

结果：更新需求阶段，持久化追平水位；设计和任务保留但标记阶段陈旧。下一轮可从新权威规格继续追平设计。

## 直接追平到实现

某通知功能已经上线，用户确认一个小范围规则调整，并选择一次同步规格、设计、任务、代码和测试。

结果：仍按五层顺序收敛；“直接”表示一个轮次覆盖到实现，不表示跳过上游门槛。

## 拆分任务

旧任务 `T020` 同时负责邮件和站内信，当前设计要求分别验收。

结果：删除活跃 `T020`，建立未完成的 `T020-A` 和 `T020-B`；两项分别映射当前设计和测试。

## 合并任务

旧任务 `T020` 至 `T023` 负责四个连续的重复迁移步骤，新设计只需两个可独立验收步骤。

结果：建立 `T020-021` 和 `T022-023`，删除原四行；两个范围不重叠。

## 重叠工作树修改

规格文件存在用户未提交修改，且包含本轮要改的同一验收规则。

结果：评估展示冲突并停止；由用户决定把修改作为基线、纳入本轮或先自行处理。

## 无 Git 的中止恢复

文档目录没有版本控制。用户确认风险后追平两份文件，随后决定停止。

结果：契约用嵌入载荷逆序恢复，验证前态一致后删除契约；没有散落 `.bak`。

## 多仓库追平

规格在文档仓库，代码和测试在两个独立仓库。用户只授权写文档和代码仓库。

结果：契约协调三个工作根；测试仓库保持只读。若目标阶段要求更新测试，当前授权不足并保持阻塞。

## 行为残留

旧字段名已从代码删除，但序列化层仍接受旧形状，测试仍断言旧回退行为。

结果：词法扫描可能为零，行为签名仍命中；完成条件不成立，直到旧路径被移除或被当前兼容要求明确保留。
