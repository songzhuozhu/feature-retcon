# 任务重建规则

任务是否保留取决于它是否忠实表达当前权威需求，而不是过去是否完成。

## 重建受影响闭包

从更新后的需求和设计重新计算任务：

- 语义和验收结果均未改变：保留编号与完成状态。
- 语义目标仍相同，但实现或验证需要重做：保留编号，重置为未完成。
- 语义已经改变：删除旧任务，创建表达新语义的未完成任务。
- 能力已删除：删除任务及其活跃引用。
- 没有旧谱系的新工作：使用下一个普通编号。

不得通过在末尾追加“修复旧任务”的方式保留失效任务，也不默认全量重编号。

## 拆分编号

一个旧任务拆成多个可独立验收任务时，使用字母后缀：

```text
T020 → T020-A, T020-B
```

删除原 `T020` 活跃行。后缀表示当前任务谱系，不表示版本；语义无关的新任务不得借用该编号。

## 合并编号

连续旧任务合成更少的当前任务时，使用不重叠范围：

```text
T020, T021 → T020-021
T022, T023 → T022-023
```

范围任务必须完整承接该连续范围仍然有效的职责，并拥有一个独立验收结果。范围生效后删除原基础任务。非连续或语义无关的任务不能为了压缩编号而合并。

## 完成检查

任务阶段通过前逐项证明：

- 每条当前需求和设计约束至少映射到一个任务。
- 每个任务都能回溯到当前需求或设计。
- 删除和迁移工作显式存在。
- 依赖顺序支持实际执行。
- 完成状态与需要重新实现或验证的事实一致。
- 派生编号没有活跃基础行，范围编号互不重叠。
