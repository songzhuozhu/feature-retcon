# 工作流适配器与多根执行

通用核心负责权威解析、评估、确认、契约、恢复、残留和阶段门槛。适配器只把项目现有工作流映射到这些概念，不能改变授权和完成定义。

## 适配原则

检查项目声明的入口、模板、脚本和规则，再决定复用方式：

- 命令能在当前权威根原地工作、写入范围可预测、编号和状态规则兼容时，确认后直接调用。
- 命令会新建版本目录、只追加产物、重排全部编号或写入范围不透明时，复用其模板和校验规则，在权威根执行等价重建。
- 命令有 Git、网络、外部系统或新增工作根副作用时，单独取得授权。
- 不修改其他 Skill 来耦合本 Skill。

## spec-kit 适配

检测到 `.specify/` 或同类 feature 索引时：

1. 读取当前 feature 映射和项目脚本，不用最大目录编号猜测权威根。
2. 把 specification、plan、tasks、implementation 和 analysis 映射到语义阶段。
3. 在只读评估中检查命令的实际写入路径、追加行为、编号策略和前置条件。
4. 只调用符合原地追平边界的命令；其余能力拆为模板、检查清单或只读分析复用。
5. 更新项目 feature 映射、水位和阶段陈旧状态，使后续命令不会误用旧产物。

项目使用其他规格工具时采用同一映射过程，不要求固定文件名。

## 多工作根与多仓库

一份契约可以协调多个确认的工作根。每个根独立记录：

- 角色和绝对路径。
- Git 边界、基线和未提交状态。
- 用户授予的读写权限。
- 验证命令、Hook 和副作用。
- 恢复来源与漂移结果。

权威根承载唯一契约；其他根不创建并行契约。执行时仍对每个目标文件调用同一写前协议。新发现的工作根默认只读；需要写入时按实质范围扩张处理。

## Hook

先分类、后运行：

- 已确认闭包内的本地 Hook：在相应阶段执行并记录结果。
- Git、网络、外部服务或新增根 Hook：等待单独授权。
- optional Hook：默认跳过并报告。
- mandatory Hook 与授权边界冲突：阻塞，不能自动越界。

Hook 产生的新文件也必须位于可写根，并遵守写前协议或由用户明确授权的可恢复生成流程覆盖。
